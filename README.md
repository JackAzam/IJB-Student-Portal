# IJB Student Portal

A Django-based local-first portal for LPK student and placement operations. The repository includes the four project specification documents and an initial connected application foundation.

> **Release status:** This is a runnable development MVP foundation, not a production-certified system. The core account, profile, event, ticket, private-document access, operational data models, and Django Admin workflows are included. Google/LINE integrations, automated document processing, full staff-facing workflow screens, and production hardening remain follow-up implementation work. Do not upload real passport, medical, or employment records until the security review and deployment checklist are completed.

## 1. Requirements

- Windows 10/11 or another Python-supported OS
- Python 3.11 or newer
- Internet access for the initial dependency installation

## 2. Install on Windows PowerShell

Open PowerShell in the extracted project folder:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Staff invitation codes are generated individually by a Superuser in Django Admin under **Staff registration codes**. The raw code is shown only once after creation; copy it immediately and share it only with the intended staff member. Codes are one-use, can have an expiry date, and can be revoked.

For the first local run, `DEBUG=True` is acceptable only on your own computer. It is not safe for a public tunnel.

## 3. Initialize database

```powershell
python manage.py makemigrations portal
python manage.py migrate
python manage.py seed_defaults
python manage.py createsuperuser
python manage.py check
```

`seed_defaults` creates JFT A2, JLPT N4, SSW exam rules, initial job types, the initial document checklist (including separate unsigned/signed Form 1-14 entries), and the baseline LPK Staff permission group. Retake waiting days are intentionally blank until the LPK enters a verified rule.

## 4. Start the portal

```powershell
python manage.py runserver
```

Open <http://127.0.0.1:8000/>.

- Student registration is open and students can log in immediately.
- Staff registration requires a one-time invitation code generated by a Superuser in Django Admin.
- Staff accounts receive baseline admin access with view/add/change permissions for operational records, but no delete permissions and no superuser privileges.
- The superuser account should be reserved for the designated system administrator.

### Generate a staff registration code

1. Sign in with the Superuser account at `/admin/`.
2. Open **Staff registration codes** and choose **Add Staff registration code**.
3. Optionally set an expiry date/time, then save.
4. Copy the one-time code from the green success message and send it privately to the intended staff member. The raw code is displayed only once; the database stores only its hash.
5. The staff member opens `/register/`, selects **Staf LPK**, and enters the code. A successful registration consumes the code.

Only Superusers can create, view, revoke, or manage invitation records. Each code is single-use; used, expired, or revoked codes are rejected. Staff created this way are never Superusers.

## 5. Main routes

| Route | Purpose |
|---|---|
| `/` | Role-aware dashboard |
| `/register/` | Student/staff self-registration |
| `/login/` | Login |
| `/profile/` | Student profile |
| `/events/` | Calendar event list |
| `/events/new/` | Student creates an event |
| `/tickets/` | Student's own tickets / staff ticket overview |
| `/tickets/new/` | Student creates a support ticket |
| `/documents/` | Documents visible to student / staff document overview |
| `/admin/` | Staff operations through Django Admin |

## 6. Important business rules represented

- Matching Job is a student pathway/program selection; orders separately identify Internship or Tokutei Ginou.
- TO/JO, TSK/KUMIAI, receiving company, job type, and location are relational records.
- Exam attempts are retained as separate records. Retake dates are calculated only when a verified number of waiting days is configured; otherwise staff must confirm manually.
- Interview history is retained. The `select_offer` service only selects offers linked to passed interviews and records the previous selection in an audit entry.
- Internship passport cases can be configured to require recommendation-letter coordination; Tokutei Ginou should not be assigned that step by default.
- Student document access is private and requires explicit `visible_to_student=True`; the media directory is not exposed through a public media URL.
- Form 1-14 unsigned and signed documents are separate checklist entries.
- Students can only list their own events and tickets, and can only download their own published documents.

## 7. Staff workflows in the initial MVP

After logging in, staff use the Admin link or `/admin/` to create and manage organizations, contacts, receiving companies, job types, TO/JO orders, assignments, exam attempts, medical checks, interviews, offers, passport cases, document requirements/versions, visits, communications, tickets, and audit entries.

The initial dashboard and student self-service pages are intentionally small. A later phase should replace admin-only operational workflows with dedicated staff screens and approval flows.

## 8. Tests

```powershell
python manage.py test
```

The tests cover basic student dashboard scoping, staff registration code enforcement, preserving interview history during offer selection, and blocking selection of an offer from a failed interview. Python syntax compilation was checked while packaging; Django runtime tests still need to be run after installing dependencies in your environment.

## 9. Backups

Stop the development server before copying `db.sqlite3`. Back up the database and `private_uploads/` together and store the backup in a restricted location. Test restoring to a separate copy before relying on the backup. Never put student documents in a public/shared folder.

## 10. Before any public/tunnel access

1. Set `DEBUG=False`.
2. Generate a unique strong `SECRET_KEY` and set it in `.env`.
3. Set exact `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS`.
4. Configure HTTPS at the trusted reverse proxy/tunnel and verify secure cookies.
5. Replace Django's development server with a production WSGI server (for example Waitress on Windows) and configure the proxy correctly.
6. Restrict staff enrollment code distribution and rotate it if exposed.
7. Review user permissions, file upload validation/scanning, backup encryption, audit retention, and data retention policy.
8. Test student-to-student access isolation and authorized document download.

A tunnel provides network access, not uptime. If the host PC/tablet is off, disconnected, or sleeping, the portal will be unavailable.

## 11. Integrations

The data model contains Google Calendar sync identifiers/status and document metadata foundations. Real OAuth setup, Drive permission mediation, Calendar synchronization/retry jobs, and LINE staff reminders are not enabled in this initial build. Do not store OAuth or LINE secrets in source code.
